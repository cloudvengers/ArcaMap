# ArcaMap

## 1. 서비스 소개

ArcaMap은 전 세계의 저장소와 보존 시설을 지도에서 탐색하는 서비스입니다. 종자은행, 유전자원센터, 기록보존소 등이 무엇을 보존하고 있으며 재난·문명 붕괴 이후 생태계와 문명의 복원에 어떤 가치가 있는지 살펴볼 수 있습니다. 사용자는 검색과 분류·보존 유형·등급 필터를 통해 장소를 찾고 위치와 보존 내용, 관련 정보를 확인할 수 있습니다.

ArcaMap은 Terraform 기반의 코드형 인프라(IaC)를 통해 AWS 리소스를 프로비저닝하고 리소스의 수명 주기를 제어합니다.

ArcaMap은 현재 운영 중인 서비스로, 애플리케이션 소스 코드는 비공개로 관리합니다. 이 저장소에서는 Terraform 기반의 인프라 구성과 설계·운영 문서를 공개합니다.

## 2. 인프라 설계 및 운영 목표

ArcaMap의 인프라는 가용성, 확장성, 접근 통제를 중심으로 설계합니다. 다중 가용 영역 구성을 통해 장애에 대비하고 CPU 부하 기반의 오토 스케일링으로 API 처리 용량을 조절합니다. AMI 기반 배포로 실행 환경의 일관성을 유지하며 로그와 지표를 통해 서비스 상태를 모니터링합니다.

### 2.1 서비스 요구사항 및 제약 조건

- **운영 우수성**: 인프라 변경과 AMI 배포를 코드로 자동화합니다. 로그·지표 기반의 관측성을 확보하여 운영 상태와 장애 원인을 파악합니다.
- **보안**: 네트워크 격리와 접근 권한 제한으로 시스템과 데이터를 보호하고 악성 IP의 접근·DDoS·웹 취약점 공격을 탐지합니다.
- **안정성**: 다중 가용 영역과 자동 장애 조치(Failover)로 서비스 중단을 최소화하고 백업을 통해 데이터 복구를 지원합니다.
- **성능 효율성**: 처리 용량은 CPU 부하 기반의 수평 확장으로 조절하고 콘텐츠 응답 지연과 오리진 부하는 CloudFront 캐싱으로 줄입니다.
- **비용 최적화**: 수요에 따라 인스턴스 수를 조절하여 유휴 비용을 줄이고 자동 확장에 따른 비용 증가는 인스턴스 수와 스토리지 용량의 상한으로 제한합니다.
- **지속 가능성**: 부하 감소 시 인스턴스를 축소하고 보존 기간이 지난 로그를 정리하여 불필요한 컴퓨팅·스토리지 사용과 이에 따른 환경 영향을 줄이는 것을 목표로 합니다.

- **배포 제약**: Terraform의 AMI 참조로 새 이미지 생성 후 인스턴스가 자동 교체되며 현재 교체 정책은 정상 인스턴스 유지를 보장하지 않아 API 중단이 발생할 수 있습니다.
- **알림 제약**: CloudWatch 경보의 운영자 알림은 구성하지 않았습니다.

### 2.2 인프라 설계

- **다중 가용 영역 구성**: 서울 리전의 두 가용 영역에 ALB·API 인스턴스·NAT Gateway와 RDS의 주·대기 인스턴스를 분산 배치하여 단일 가용 영역 장애에 대비합니다. Application Load Balancer(ALB)의 요청 분산, Auto Scaling 그룹(ASG)의 인스턴스 자동 복구, Amazon RDS for PostgreSQL의 Multi-AZ 장애 조치를 통해 서비스 가용성을 확보합니다.
- **네트워크 격리 및 접근 통제**: ALB는 퍼블릭 서브넷에, API 서버와 RDS는 각각 분리된 프라이빗 서브넷에 배치합니다. 보안 그룹으로 ALB → API → RDS 통신을 제한하며 운영 접속에는 SSH 포트 개방 없이 AWS Systems Manager Session Manager를 사용합니다.
- **정적 콘텐츠 제공 분리**: 웹과 지도 데이터는 Amazon S3와 CloudFront를 통해 제공하고 API 요청은 ALB로 전달합니다. S3 오리진 접근은 Origin Access Control(OAC)과 버킷 정책으로 해당 CloudFront 배포에 제한합니다.
- **웹 위협 탐지**: CloudFront에 AWS WAF 웹 ACL을 연결하여 악성 IP·DDoS·웹 취약점 공격을 검사합니다. 관리형 규칙 그룹의 판정 결과는 Count 모드로 집계하고 보안 로그와 지표를 CloudWatch에 수집합니다.
- **AMI 기반 배포**: EC2 Image Builder로 API와 의존성을 포함한 Amazon Machine Image(AMI)를 생성합니다. Terraform이 시작 템플릿에 AMI를 반영하면 ASG Instance Refresh가 인스턴스를 교체합니다.
- **인증정보 및 권한 관리**: RDS 인증정보는 AWS Secrets Manager에 저장하고 API 서비스 시작 시 조회합니다. 운영 인스턴스와 이미지 빌드 인스턴스의 IAM 역할을 분리하며 인증정보 조회 권한을 지정된 Secret으로 제한합니다.

### 2.3 서비스 운영 목표

- **장애 감지 및 복구**: EC2 상태 검사와 ALB 헬스 체크를 기준으로 비정상 인스턴스를 교체하고 API 응답과 데이터베이스 연결을 각각 점검합니다.
- **처리 용량 관리**: 평균 CPU 사용률 50%를 목표로 API 인스턴스를 2~4대 범위에서 자동 조절합니다. RDS 스토리지는 지정된 용량 상한 내에서 자동 확장합니다.
- **모니터링 및 장애 분석**: CloudWatch로 인스턴스 상태, HTTP 5xx 오류, CPU·메모리·스토리지 지표를 감시합니다. 인프라 로그는 CloudWatch Logs에, CloudFront 접근 로그는 S3에 보존하며 API 프로세스 로그를 함께 활용해 장애 원인을 분석합니다.
- **데이터 복구**: RDS 자동 백업을 3일간 보존하고 삭제 보호와 최종 스냅샷을 적용합니다. 데이터 오삭제와 잘못된 변경은 백업·스냅샷을 통한 복구 대상으로 관리합니다.
- **배포 검증**: Instance Refresh 완료 후 인스턴스의 서비스 등록 상태, ALB 헬스 체크, API 응답 및 RDS 연결을 확인합니다.

**개선 목표 — 미적용**

| 항목 | 개선 목표 |
|---|---|
| 배포 가용성 | 기존에는 AMI 생성 후 AMI 값을 수동으로 변경해야 했으므로 Terraform의 AMI 참조로 새 이미지 생성 후 인스턴스가 자동 교체되도록 구성했습니다. 신규 인스턴스의 정상 상태를 확인한 뒤 기존 인스턴스를 종료하도록 교체 정책을 개선합니다. |
| 경보 알림 | CloudWatch 경보에 Amazon SNS를 연동하여 운영자 알림을 구성합니다. |
