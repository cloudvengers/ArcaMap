# Security Groups(계층별 접근 통제)

**ALB·API·데이터베이스 사이의 통신을 역할과 포트로 제한하는 보안 그룹 구성**

외부 요청의 진입점과 내부 처리 계층을 구분하고 필요한 연결만 허용합니다. 통신 상대는 개별 서버 IP가 아니라 보안 그룹으로 지정합니다. 인스턴스를 교체해도 역할별 통신 범위는 유지됩니다.

## 1. Access Rules(접근 규칙)

| 보안 그룹 | 방향 | 상대 | 포트 |
|---|---|---|---|
| ALB | 인바운드 | 전체 IPv4 | TCP 80·443 |
| ALB | 아웃바운드 | API 보안 그룹 | TCP 8080 |
| API | 인바운드 | ALB 보안 그룹 | TCP 8080 |
| API | 아웃바운드 | DB 보안 그룹 | TCP 5432 |
| API | 아웃바운드 | 전체 IPv4 | TCP 443 |
| DB | 인바운드 | API 보안 그룹 | TCP 5432 |

## 2. Traffic Flow(통신 흐름)

1. 외부 요청은 ALB 보안 그룹의 공개 포트로 들어옵니다.
2. ALB는 API 보안 그룹의 8080 포트로 요청을 전달합니다.
3. API는 DB 보안 그룹의 5432 포트로 데이터베이스에 연결합니다.
4. API의 외부 HTTPS 연결에는 443 포트를 사용합니다.

## 3. Design Principles(설계 원칙)

- **역할별 허용** — 공개 요청·API 처리·데이터베이스 연결마다 허용할 통신 상대를 정합니다.

- **보안 그룹 참조** — 서버 IP 대신 상대 보안 그룹을 지정합니다. 같은 역할의 인스턴스에는 같은 규칙을 적용합니다.

- **관리 접속 분리** — SSH 인바운드 포트를 열지 않고 Session Manager를 사용합니다.

보안 그룹이 연결 상태를 추적하므로 허용된 연결의 응답 트래픽에는 별도의 역방향 허용 규칙이 필요하지 않습니다.
