# EC2 Image Builder(API 이미지 생성)

**📦 API와 의존성을 포함한 AMI를 생성하는 이미지 빌드 구성**

애플리케이션과 실행에 필요한 환경을 이미지에 담아 API 서버가 같은 환경에서 실행되도록 합니다. 빌드·테스트를 거쳐 생성한 AMI는 시작 템플릿과 인스턴스 교체에 사용합니다.

## 1. Image Architecture(이미지 구성)

| 구성 요소 | 역할 |
|---|---|
| **이미지 레시피** | 이미지의 기반과 구성요소 조합 |
| **빌드 구성요소** | API와 의존성을 포함한 실행 환경 준비 |
| **테스트 구성요소** | 빌드 이미지의 테스트 수행 |
| **빌드 인스턴스** | 이미지 생성 작업을 수행하는 환경 |
| **AMI** | 운영 API 인스턴스의 기반 이미지 |

## 2. Build Flow(이미지 생성 흐름)

1. 이미지 빌드 환경에서 배포용 S3의 **API 아카이브**를 가져옵니다.
2. API와 실행에 필요한 의존성을 이미지에 포함합니다.
3. 이미지를 테스트합니다.
4. 생성된 **AMI**를 API 서버의 시작 템플릿에 연결합니다.
5. Auto Scaling Group의 인스턴스 교체에 새 이미지를 사용합니다.

## 3. Access Control(접근 통제)

- 🔑 **역할 분리** — 이미지 빌드 인스턴스의 IAM 역할을 운영 API 인스턴스 역할과 분리합니다.

- 📦 **배포 객체 접근** — 빌드에 필요한 S3 객체를 지정하고 해당 객체의 읽기 권한을 부여합니다.

- 🛡️ **네트워크 배치** — API 프라이빗 서브넷과 보안 그룹으로 빌드 인스턴스가 통신할 수 있는 범위를 정합니다.

## 4. Operational Constraints(운영 제약)

> **배포 연결**: 생성된 AMI는 시작 템플릿과 연결됩니다. 현재 정책으로 인스턴스를 교체하면 API가 중단될 수 있습니다.
