# Network(네트워크 배치와 통신 경로)

**두 가용 영역에 공개 진입점·API·데이터베이스를 분리하는 VPC 구성**

퍼블릭·API·DB 서브넷을 역할별로 나누고 외부 통신 경로에는 Internet Gateway와 NAT Gateway를 사용합니다. API는 NAT를 통해 외부에 연결하며 DB는 외부 기본 경로 없이 VPC 내부에서 통신합니다.

## 1. Network Architecture(네트워크 구성)

| 항목 | 구성 |
|---|---|
| VPC | 10.0.0.0/16 |
| 가용 영역 | ap-northeast-2a·ap-northeast-2c |
| 서브넷 | 퍼블릭·API·DB 각각 2개 |
| NAT Gateway | 가용 영역별 1개 |

### 서브넷 배치

| 용도 | ap-northeast-2a | ap-northeast-2c |
|---|---|---|
| 퍼블릭 | `10.0.1.0/24` | `10.0.2.0/24` |
| API | `10.0.11.0/24` | `10.0.12.0/24` |
| DB | `10.0.21.0/24` | `10.0.22.0/24` |

## 2. Traffic Paths(통신 경로)

- **공개 진입점** — 퍼블릭 서브넷의 기본 경로는 Internet Gateway로 향합니다. 이 서브넷에 ALB와 NAT Gateway를 배치합니다.

- **API 외부 통신** — API 서브넷은 같은 가용 영역의 NAT Gateway를 기본 경로로 사용합니다.

- **DB 통신** — DB 서브넷은 VPC 내부 경로를 사용하며 인터넷으로 향하는 기본 경로를 두지 않습니다.

## 3. Design Principles(설계 원칙)

| 원칙 | 목적 |
|---|---|
| 역할별 배치 | 공개 진입점·애플리케이션·데이터 저장 영역을 구분합니다. |
| 가용 영역 분산 | 두 가용 영역에 같은 역할의 서브넷을 배치합니다. |
| 가용 영역별 NAT | API는 같은 가용 영역의 NAT를 거쳐 외부와 통신합니다. |

라우팅은 패킷의 전달 경로를 결정합니다. 실제로 허용할 통신 범위는 각 리소스의 보안 그룹이 제한합니다.
